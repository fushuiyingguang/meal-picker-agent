# 设计规范

## 设计原则
1. **单一职责**：模块/函数只做一件事，边界清晰。
2. **依赖方向**：入口层 → 业务层 → 数据层，单向依赖，不反向引用。
3. **可测试优先**：核心逻辑不依赖 I/O，便于单元测试。
4. **最小实现**：先用最简单方案满足当前需求，不过度设计。

## 架构分层（建议）
| 层 | 职责 | 示例 |
| --- | --- | --- |
| 入口层 | 解析参数/请求、组装调用 | `__main__.py` / API 路由 |
| 业务层 | 核心决策逻辑（推荐算法） | `service/` |
| 数据层 | 数据来源与持久化 | `repository/`、外部 API 客户端 |

## 接口与数据设计
- 对外接口（CLI 参数 / HTTP API）需在代码或文档中明确输入输出契约。
- 数据结构用 `dataclass` / `pydantic` 明确定义字段与类型。

## 错误处理
- 业务异常使用自定义异常类，由入口层统一捕获并转换为用户可读信息。
- 不吞异常；外部调用失败需重试或明确失败原因。

## 日志
- 使用标准 `logging`，区分 `DEBUG/INFO/WARNING/ERROR`。
- 日志不得包含敏感信息（密钥、个人隐私）。
