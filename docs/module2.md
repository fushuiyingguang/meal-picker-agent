# 模块二：智能筛选与摇号

对应页面：`pages/2_picker.py`

## 功能定位
决策核心模块：支持五种用餐模式一键预设，在分类 / 口味 / 总预算 / 位置距离等多条件筛选下，按就餐人数智能搭配「一桌菜」（荤素搭配、分类分散、总价不超预算），支持随机摇号与一键重摇，并一键生成选餐记录。位置以**中原工学院（郑州龙湖校区，lat=34.626, lng=113.705）**为默认地理中心。

## 输入数据
- 用餐模式（五选一，切换后自动联动下方筛选条件）：
  - 单人简餐：1 人、总预算 10-25 元、距离 1000 米、口味清淡/咸
  - 朋友小聚：3 人、总预算 20-60 元、距离 3000 米、小吃/烧烤、偏荤
  - 家庭聚餐：5 人、总预算 30-100 元、距离 5000 米、荤素搭配
  - 公司聚餐：8 人、总预算 50-150 元、距离 5000 米、中餐/快餐、偏荤
  - 社团团建：6 人、总预算 30-80 元、距离 3000 米、烧烤/小吃
- 我的位置：纬度 / 经度（手动输入，或点「📍 定位到中原工学院」一键回填）。
- 筛选条件：总预算区间（元，滑条，代表**整桌菜总价**）、距离（公里，滑条）、就餐人数（1-10 人，滑条）、分类（多选）、口味（多选）。
- 候选菜品来源：菜品库（含 16 条演示数据 + 团队实地采集北苑1楼77条真实菜品数据）。

## 处理逻辑
1. **模式预设**：切换用餐模式时通过 `on_change` 回调同步各筛选控件的值（总预算/距离/就餐人数/分类/口味），并提示「当前模式：X，已为您自动调整筛选条件」。
2. **候选集计算（实时）**：先按分类（可多选）/口味在 `dishes` 表内筛选，再用 Haversine 公式按经纬度计算与用户位置的直线距离，只保留 ≤ 距离滑条值的菜品，按距离升序；每次改动后自动重算并显示候选数量。聚餐模式（非「单人简餐」）额外剔除早餐品类（包子/粥/鸡蛋/油条/豆浆/胡辣汤/馒头/烧麦），「鸡蛋灌饼」等正餐小吃保留。
3. **菜品数量（N+1 / N+2 法则）**：1 人 → 1 道菜；2-5 人 → N+1 道；6 人以上 → N+2 道。
4. **荤素搭配**：按荤素倾向确定荤菜占比（默认 60% 荤 + 40% 素；偏荤 70%、偏素 40%），并保证 ≥2 道菜时至少 1 荤 1 素；某类不足时用另一类补足，菜品尽量覆盖不同分类。
5. **总预算校验**：随机抽取一桌菜后计算整桌总价，落在总预算区间内即采用；否则重抽（最多 50 次），仍无法满足则触发「条件冲突提示」。
6. **随机摇号 / 一键重摇**：点「摇一摇」按上述规则抽一桌菜；「🔄 一键重摇」排除刚摇出的菜品重新抽一桌，无可选时提示「已没有其他选择啦，请放宽筛选条件」。
7. **生成记录**：点「选定并记录」把整桌菜写入 `records`（source=draw）。
8. **条件冲突提示**：候选集为空或候选不足以搭配、预算区间内无法成桌时，提示放宽预算/减少人数/扩大距离/去掉口味，并提供「♻️ 一键重置筛选条件」按钮（回到「单人简餐」默认模式）。

## 输出结果
- 「当前符合条件：N 道」候选数量 + 候选菜品列表（菜名/分类/荤素/价格/距离）。
- 「🍽️ 为您搭配的一桌菜」标题 + 「就餐人数：X 人 · 这桌菜预估总价：¥XX 元」，逐道展示（菜名/分类/荤素/价格/距离）。
- 「🔄 一键重摇」结果（新一桌菜，与上一桌无交集）。
- 空候选集或无法成桌时的「条件冲突提示」+「♻️ 一键重置筛选条件」。
- 重摇无其他可选时提示「已没有其他选择啦，请放宽筛选条件」。
